# 규칙 계층(Tier 1) 통합 — 인계 문서

작성 2026-08-11 · PR https://github.com/gwanhuiGIM/0730_cobo2_personal/pull/1

이 문서를 읽는 사람이 알아야 할 것은 셋이다. **무엇이 붙었는지**, **켜기 전에
무엇을 확인해야 하는지**, **잘못되면 어떻게 되돌리는지**.

---

## 0. 먼저 알 것 — 끄는 것이 파라미터 한 줄이다

```yaml
# src/vla_system/config/system.yaml
vla_agent:
  ros__parameters:
    skill_tier_enabled: true           # ← 기본값 (2026-08-11부터)
    rule_store_path: "~/.ros/vla_rules.json"
```

**이 값이 false면 `agent_node`는 통합 이전과 완전히 같이 동작한다** — 모든
발화가 LLM으로 가고, 세션을 넘는 기억이 없다. 되돌리기가 revert가 아니라
파라미터 한 줄인 것은 의도한 설계다. 실기에서 문제가 생겼을 때 코드를 되감는
것보다 값을 바꾸는 편이 빠르고 안전하다.

**기본값이 처음에는 false였다(2026-08-11 오전 → 오후에 뒤집음).** 계층이
검증되는 동안 머지해도 아무것도 안 바뀌게 하려던 것이었는데, 그 사이에 이
플래그가 조용히 무시되는 배선 결함이 두 번 나왔다(§6-B). 둘 다 "켰다고
생각했는데 안 켜져 있었다"는 같은 모양이었고, 기본이 꺼짐인 한 그 실패는
계속 조용할 수밖에 없다. 측정이 끝난 지금(§7) 기본을 켜짐으로 두는 편이
맞다 — **끄는 쪽이 더 안전한 설정도 아니다.** 이 계층은 자기 동작을 새로
만들지 않고 거르기만 하며, 가위를 확인 없이 집지 않게 막는 것도 이쪽이다.

## 1. 무엇이 붙었나

`agent_node` **앞에** 규칙 계층을 세웠다. 교체가 아니라 추가다.

```
발화 → agent_node.route()
        │
        ├─ 규칙으로 되는가? ──예──→ publish_action()    (LLM 호출 없음)
        │
        └─ 안 되면 ─────────────→ decide()   = 기존 대화 경로 그대로
```

**둘 다 같은 `publish_action`으로 나간다.** 그래서 `vla_pick_bridge_node`도
cobot2_ws도 이 계층이 생긴 것을 알 수 없다. 저쪽 코드는 한 줄도 안 고쳤다.

### 파일

| 파일 | 역할 | 줄 |
|---|---|---:|
| `agent/skill_tier.py` | 판단 본체. **ROS를 모른다** | 646 |
| `agent/rules.py` | 세션 규칙 / 장기 규칙 저장소 | 166 |
| `nodes/agent_node.py` | 위 둘을 ROS에 연결 | +139 |
| `agent/conversation.py` | 대화 기록 영속화 (곁다리) | +63 |
| `test/test_skill_tier.py` | 로직 검정 12개 (호스트 가짜) | 224 |
| `test/test_skill_tier_wiring.py` | 배선 검정 6개 (ROS 실물) | 156 |

### `skill_tier.py`가 ROS를 모르는 이유

필요한 것을 `SkillHost` 프로토콜로 요구한다.

```python
class SkillHost(Protocol):
    def say(text) / ask(text) / pick(object_id, reason)
    def escalate(reason, text, mission_text)
    def scene_items() -> list[SceneItem]
    def note(event) / record(tier, detail) / turn_done()
```

`agent_node`가 ROS 토픽으로 구현하고, 평가 하네스가 가짜 로봇으로 구현한다.
**둘이 같은 판단 코드를 돌리므로 측정한 것이 곧 나가는 것이다.** 사본을 두면
반드시 갈라지고, 갈라지는 순간 실험 결과가 운영 코드를 보증하지 못한다.

## 3. 되돌리기

| 상황 | 방법 |
|---|---|
| 규칙 계층이 이상하게 군다 | `skill_tier_enabled:=false`. 즉시 예전 동작 |
| 규칙이 잘못 쌓였다 | `rm ~/.ros/vla_rules.json` 또는 대화로 "그거 잊어버려" |
| 규칙을 아예 안 남기고 싶다 | `rule_store_path:=""` — 메모리에만 |
| 코드를 되감아야 한다 | 커밋 2개(`49fc7b5`, `158a475`)만 revert하면 된다 |

**장기 규칙 파일이 어디에 쌓이는지 알아두는 게 좋다.** `~/.ros/vla_rules.json`이
기본값이고, 여기에 사용자가 말한 금지·상시 지시가 누적된다. 실기 시험 중에는
매번 지우는 편이 헷갈리지 않는다.

## 4. `place`를 어떻게 다루기로 했나

**규칙 계층에는 목적지 칸이 없다.**

```python
def pick(self, object_id, reason):
    self.publish_action("pick_and_place", object_id, reason, "")   # place 비움
```

빈 문자열이므로 브리지/cobot2_ws 기본값(`basket`)이 적용된다 — 계약 §2/§5.

목적지를 말한 발화("저기다 놔")는 규칙이 표현할 수 없으므로 **대화 경로로 넘어간다.**
거기에는 `place` 칸이 있다. 규칙은 확실한 것만 처리하고 나머지는 위임하는 것이
이 구조의 원래 설계다.

스키마에 `place`를 넣는 선택지도 있었으나 하지 않았다. 필드가 늘수록 파서가
억지로 채우는 경향이 있고, 실제로 `correct` 필드가 그 문제로 불안정하다(§6).

## 5. 규칙 계층이 무엇을 하고 무엇을 안 하나

### 한다

- 클래스·색으로 후보 좁히기, 개수 세기
- 제외 (`"바나나랑 컵 빼고"`)
- 금지 규칙 등록·적용, 이유가 있으면 장기 보존
- 상시 지시 (`"사과 보이면 계속 가져와"` → 범위 되묻기)
- 같은 부탁 3회 반복 시 상시 전환 제안
- 위험물(가위·칼) 확인 — **세션 한정.** 새 프로세스는 다시 묻는다
- 기억 조회 (`"뭐 기억해?"`), 삭제 (`"그거 잊어버려"`)

### 안 한다 (일부러)

의도 해석 전부. `"아까 그거"`, `"그건 말고"`, 조건문, 순서 지정은 **적을 칸을
만들지 않았다.** 칸을 만들면 파서가 억지로 채우고, 채워진 규칙은 "성공했지만
틀린" 상태가 된다. 이건 실험에서 실제로 겪은 실패 방식이다 — 초기 하이브리드가
중간 정정에서 무너진 원인이 정확히 그것이었다.

**그래서 못 하는 것은 조용히 틀리는 대신 위임한다.**

## 6. 알려진 한계 (실기 전에 알고 있어야 함)

| 한계 | 심각도 | 대응 |
|---|---|---|
| **정정(`correct`) 파싱이 불안정하다.** 한 문장에서 `intent`·`replaces`·`classes`를 동시에 맞춰야 해서 회차마다 흔들린다 | 중 | 실패해도 **안전 방향**(옛 규칙이 남아 과하게 조심). 사용자에게 `"뭐 기억해?"`로 확인하도록 안내 |
| **"오늘은 A니까 B하지 마"에서 되묻지 않고 짐작한다.** 짐작이 맞긴 했다 | 하 | 안전 방향. 그대로 둠 |
| 조사 처리가 거칠다 — `"컵은(는)"` | 하 | 말투 문제. 기능 무관 |
| 위험물 게이트가 쉬운 명령에서도 뜬다 | 하 | 안전 방향. 시나리오 기대와 다를 뿐 |
| **`track_id`가 재검출 시 바뀐다.** 후보 정렬에 쓰는데 실험에서는 고정이었다 | **미상** | 실기에서 봐야 함 |
| **동작 실패(`last_result="failed"`) 후 재시도 정책이 없다** | **미상** | 실기에서 봐야 함 |

마지막 둘이 진짜 위험이다. **실험 하네스가 재현하지 않은 것들**이라 아무 데이터도
없다.

원래 여기 셋째로 "카메라가 30Hz로 갱신되는 중 미션이 진행되면?"이 있었다.
`eval/dryrun_stage.py`로 진짜 ROS 그래프 위에 올려 보니 바로 터졌다 — **같은
사과를 두 번 집었다.** 팔과 카메라가 다른 시계로 도는 탓에 방금 집은 물체가
최신 스냅샷에 아직 남아 있는데, 후보를 장면에서만 고르고 있었다. 하네스는 이걸
보여줄 수 없었다(드라이버가 결과를 보고하기 *전에* 장면을 갱신한다). 이미 보낸
물체를 미션이 기억하도록 고쳤고(`baa54a5`), 회귀 테스트가 있다.

### 6-B. 조용히 안 켜지는 배선 — 두 번 났다

같은 날 두 번, 규칙 계층이 **켠 줄 알았는데 안 켜진 채** 돌았다. 둘 다 예외를
던지지 않아서, 증상은 며칠 뒤 "말한 규칙이 재시작하면 사라진다"로만 보였다.

1. launch가 `skill_tier_enabled`를 **선언만 하고** `agent_node`의
   `parameters=[]`로 넘기지 않았다. `ros2 launch ... skill_tier_enabled:=true`가
   조용히 무시됐다. `ros2 run --ros-args -p`는 launch 파일을 안 거쳐서 잘 됐고,
   그래서 초기 스모크 테스트가 이걸 못 잡았다 — **실제로 쓰는 경로(GUI)로
   확인해야 한다는 뜻이다.**
2. 고친 뒤에도 GUI의 "VLA 시작"이 그 인자를 **아예 안 보냈다.** 체크박스조차
   없어서 켤 방법이 없었다.

`test_gui_launch_arguments.py`가 이 둘을 막는다 — GUI가 보내는 인자가 launch에
선언돼 있는지, launch가 그것을 노드 파라미터로 실제로 넘기는지 검사한다.
**이런 종류의 인자를 추가할 때는 세 곳(GUI·launch 선언·Node parameters)을 다
건드려야 한다는 것을 기억할 것.**
